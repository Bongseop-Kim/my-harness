# E2E 테스트 실행 하네스

## 원칙
E2E는 반복 루프가 아니라 체크포인트에서만 실행한다.
코드 수정 → 확인 → 재수정의 빠른 반복은 유닛/통합 테스트로 처리하고,
E2E는 경계를 넘거나 의미 있는 단위가 끝났을 때만 통과 관문으로 쓴다.
**기본값은 "실행하지 않음"** 이며, 아래 판단을 통과할 때만 실행한다.

## 판단 순서
1. 실행 조건에 해당 → 실행 (핵심 경로는 리팩터링이어도 실행)
2. 스킵 조건에 해당 → 실행하지 않음
3. 애매하면 GATE로 결정
※ 실행 조건의 "변경"은 동작·계약에 영향을 주는 변경만 뜻한다. 단순 줄 이동은 제외.

## GATE (애매할 때 자문)
"이 변경으로 생긴 문제가 유닛·통합 테스트를 모두 통과하면서
 실제 사용자 경로만 깨뜨릴 수 있는가?"
- 예 → 실행
- 아니오(유닛으로 잡힘) → 스킵

## 실행 조건 (하나라도 해당하면 실행)
- 핵심 사용자 경로 변경: 로그인 / 결제 / 가입 / 메인 워크플로
- 경계를 넘는 변경: API 계약, 서비스 간 통신, 외부 연동, DB 스키마·마이그레이션
- 다수 흐름에 영향: 라우팅, 인증·세션 미들웨어, 전역 설정
- 규모 있는 기능 완성 직후 또는 머지·배포 직전
- 유닛/통합 커버리지가 약해 E2E가 유일한 안전망인 영역
- 과거 E2E가 잡은 버그의 회귀 수정

## 스킵 조건 (실행하지 말 것)
- 동작 변화 없는 리팩터링 (핵심 경로 제외)
- 유닛으로 충분히 잡히는 고립 로직
- 스타일·문구·문서·주석 변경
- 기능 개발 중간 단계 (끝에 몰아서 실행)
- 방금 실행했고 이후 커버된 경로를 안 건드림

## 실행 방식 (토큰·시간 최소화)
- 전체 스위트 대신 영향받은 흐름만 태그/필터로 선택 실행
- 출력 전문을 읽지 말 것. 종료 코드 + 실패 요약(테스트명·에러 1줄)만 확인
- 앱·인증 세션은 재기동·재로그인 없이 재사용
- 전체 회귀 스위트는 가능하면 CI에 위임하고, 결과만 읽는다

## 보고 형식
실행 시:  [E2E] 대상:<흐름> | 이유:<조건> | 결과:PASS/FAIL(<n>건) | 실패:<요약>
스킵 시:  [E2E skip] 이유:<스킵 조건 한 줄>
